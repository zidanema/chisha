# 今天吃点啥 · chisha

> 佛说，人生三大难题：早上吃什么、中午吃什么、晚上吃什么？

健康饮食的道理都懂，但每餐到底吃哪家、点哪个，才是那个天天要解两遍的终极拷问。**于是我做了「今天吃点啥」。**

## 我为什么做它

伤病康复后，医生说我想继续踢球，只有一条路：**加强力量、控制体重**。我想，减脂增肌不就一个“吃”字嘛，能有多难？

**结果在“怎么吃”上反复翻车。**

- **算热量** —— 二到每天带个秤去吃饭，才发现难点根本不是记录，是怎么找到那顿“热量 ok、又没那么难吃、还能持续吃下去”的饭。
- **吃健康餐** —— 戒油戒辣坚持几周，不是半夜饿到想啃被子，就是对食物充满饥渴。拿意志力硬刚生理需求，终难长久。

后来撞见**哈佛餐盘法**：一半菜、四分之一蛋白、四分之一主食，不戒一切，日常正常吃就行。道理通了——**日子却没好过多少。**

方法是有，可每顿还得对着外卖 APP 一家家审：这家凑得齐一半蔬菜吗？蛋白够吗？会不会太油？规律就那几条，候选却茫茫多，纠结十来分钟，最后经常懒得选，要么随便点一个，要么又回到吃了几十次的那三家。

忍无可忍的某天我想明白：规律就那几条，**这破事让“贾维斯”干啊。** 于是我做了个推荐系统替我选——现在每个饭点它直接按我的吃法配好几组，我扫一眼挑一个就完事，那个天天做两遍的破决策，总算不归我管了。

> 点餐推荐系统 vibe 起来愉悦又顺利，但怎么搞到周边商家和菜品的数据……说多了都是泪（此处按下不表）。所以眼下只支持深圳两个办公区 + 一个居住区，别处后续有需求再加。

**它解决谁的问题？** 跟我一样的人：已经有一套饮食目标（控油减脂、高蛋白增肌、糖控、孕期……），道理早想明白，缺的只是每天怎么轻松找到合适的供给。

**它不解决谁的问题？** 选择困难、自己也不知道想吃啥、指望 AI 猜透心思推出你爱吃的那种。

> 默认按哈佛餐盘走（控油、有菜、有蛋白）——目前就这一套方法论。“今天想清淡”“想吃辣”“少点米饭”这种**当顿口味**张嘴说就调；但**切换整套饮食法**（糖控、孕期、生酮）还没做，在路线图上。

## 它实际怎么用

装好后，在你的 AI 助手里（Claude Code、Codex，或飞书里的 OpenClaw）直接说一句"中午吃啥"：

```
你:     中午吃啥
chisha: （摆一组候选，各带餐厅+主菜+价格+一句理由，3 个稳妥 + 2 个你没试过的）
你:     选第 2 个        →  照着去外卖软件下单
你:     想吃辣、少米饭    →  它重排一组   ← 不满意随时 refine
```

> 同一套交互，**所有宿主一致**：能弹卡片的（Claude Code / 飞书）就摆成单选卡，纯命令行的（Codex 等）就摆成编号列表回数字选 —— 用哪个 AI 助手都是这个用法。

- **按你长期口味 + 今天状态筛** —— “今天想清淡”“想吃辣解馋”直接说
- **3 稳妥 + 2 探索** —— 稳得住，也帮你跳出每天那三家
- **可选画像** —— 不填也能跑；愿意配时，AI agent 只用你明确说过的饮食信号预填，确认后写入
- **饭点主动提醒（可选）** —— 用顺手了，可让它每天饭点主动给你配好（需你的 AI 助手支持定时，如 Claude Code routines / 飞书 OpenClaw cron）

## 装（Claude Code / Codex / OpenClaw 用户）

这个仓就是一份**自包含、跨宿主**的 skill 文件夹（代码 + 数据 + 依赖全在里面，运行期零联网 / 零 pip）。clone 进你 AI 助手的 skills 目录即用：

```bash
git clone https://github.com/zidanema/chisha.git ~/.claude/skills/chisha    # Claude Code
git clone https://github.com/zidanema/chisha.git ~/.codex/skills/chisha      # Codex（clone 完重启加载）
git clone https://github.com/zidanema/chisha.git ~/.openclaw/skills/chisha   # OpenClaw（飞书，寻常 skill 无需插件）

# 配区域 + 自检（<DIR> = 你刚 clone 的目录）:
python3 <DIR>/scripts/chisha onboard --zone shenzhen-bay  # shenzhen-bay / jinghu / cuihai
python3 <DIR>/scripts/chisha doctor                       # 自检
# → 之后在 AI 助手里说“今天中午吃啥”即触发
```

`onboard` 只配区域、**不问口味**（零强制）。想配忌口 / 爱吃菜系 / 辣度，跟 AI 助手说一句**“配一下画像”**，它会问几句帮你写进画像；不配也照常能用。设置 / 反馈存在 `~/.chisha/`（与 clone 位置无关，同机多宿主共享一份），`git pull` 更新不覆盖。

> **更省事**：直接跟 AI 助手说“帮我接入今天吃点啥”，它读 [AGENTS.md](AGENTS.md) 自己 clone、自检、配区域、跑通。
>
> **前提**：你得有 Claude Code / Codex（或别的能跑 shell + 调自己 LLM 的 AI agent）；python3 ≥ 3.11 在 PATH（macOS 自带 3.9 不够）；**POSIX-only**（macOS / Linux，Windows 需 WSL）。
>
> 🤖 **想在飞书里用？** chisha 就是个寻常 skill——clone 进飞书宿主（如 OpenClaw）的 skills 目录即可，说一句“中午吃啥”触发；呈现 / 选 1 / refine 全用宿主自带的问答工具（OpenClaw 的 `feishu_ask_user_question`），无需任何插件或额外安装。

## 它幕后怎么跑的（给好奇的技术同学）

三阶段推荐，但有个不常见的设计：**chisha 自己不调 LLM、不持任何 API key。**

```
L1 召回（本地，确定性）  →  L2 15 维打分（本地）  →  L3 精排写理由（借宿主 LLM）
```

- **零 key，蹭宿主最强模型**：确定性的活（召回 / 打分 / 校验 / 兜底）全在本地跑；只有需要“智能”的两步（抽意图 / 排候选），chisha 发一个机器可读的 `do_llm` 信封，**借你 AI 助手背后的 LLM** 执行后喂回。你不配 key，自动用上宿主最强的模型。
- **agent-agnostic 协议**：交互呈现是 adapter 特定的薄层；底下 `chisha eat / continue / choose` CLI + `do_llm` 信封跨 agent 通用。换宿主（codex / 飞书机器人 / 你自建 Agent）= 重写交互层、复用协议层。
- **数据不出本机**：全程在你电脑 / 你 AI 助手里跑，作者不参与运行、不接触你吃啥。

> 想看协议细节或自己接一个新宿主 → [AGENTS.md](AGENTS.md)。

## 不做什么

- **不部署服务** —— 没有云端，数据全在你电脑
- **不替你下单** —— 看完推荐，你打开外卖软件自己下
- **不绑生态** —— 用哪家 AI、哪个 IM 都行
- **不算卡路里** —— 帮你避大油、保证蔬菜蛋白，不替你精算每克热量
